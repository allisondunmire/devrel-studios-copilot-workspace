## What
Build a Bookings-style studio request experience for internal and external users. Availability comes only from `drstudios@microsoft.com`; Busy meetings and appointments block time, and no personal calendar data is used. Requests require manual approval before a Busy appointment with no attendees is created on the studio calendar.

## Architecture Decisions
- **Internal experience:** SharePoint or Power Apps page over sanitized SharePoint availability data.
- **External experience:** Power Pages public site; external users do not access SharePoint or Outlook directly.
- **Calendar source:** only `drstudios@microsoft.com` through the standard Office 365 Outlook connector. The HTTP/Graph action is blocked by DLP.
- **Request language:** use "Request studio time," not "Book" or "Confirmed."
- **Approval:** requests remain Pending until manually approved or declined.
- **Calendar write:** approval creates a Busy appointment on DRStudios with no required or optional attendees. The subject is `Stage - Session Name`.
- **Privacy:** public/internal availability contains only stage and time data. Calendar subjects, bodies, attendees, and Outlook event IDs remain internal.
- **Concurrency:** Power Automate request and decision flows use concurrency control with degree 1.

## SharePoint Lists
- **AvailableSlots:** Title/Slot Name, Stage, StartTime, EndTime, Available, TD Available, SlotDate. Rows are regenerated by selected date; reserved rows are retained.
- **StudioBookings:** Session Name/Title, Stage, StartTime, EndTime, Requester Name, Requester Email, Status, Assigned TD, Booking ID, Notes, AvailableSlotID, ApprovalProcessed, OutlookEventID.
- **StudioSettings:** StudioOpenTime 09:30, StudioCloseTime 16:00, SlotLengthMinutes 30, StageARequiresTD Yes, BufferMinutes 30, LunchStartTime 12:00, LunchEndTime 13:00.
- **Statuses:** Pending, Approved, Declined, Cancelled, Conflict.

## Power Automate Flows
- **Generate Available Slots - Calendar Test:** prompts for a date, reads only DRStudios Busy events, converts Pacific time with daylight-saving support, preserves other dates, prevents duplicates, and creates stage slots not blocked by calendar events or Pending/Approved requests.
- **Process Studio Booking Request:** triggers on a new StudioBookings row, serializes requests, validates AvailableSlotID, reserves the slot, and copies authoritative stage/time values into the Pending request. A second claimant is marked Conflict.
- **Process Studio Booking Decision:** triggers on create/modify, routes Approved/Declined, uses ApprovalProcessed to prevent duplicate work, rechecks DRStudios, creates the no-attendee Busy appointment, stores OutlookEventID, or releases the slot for Declined/Conflict.

## Notes
- **DLP:** Office 365 Outlook `Send an HTTP request` failed with status 442. `Get calendar view of events (V3)` works and exposes the DRStudios shared calendar in its Calendar ID picker.
- **Choice fields:** SharePoint Stage and Status values are objects in flow output; use `item()?['Stage']?['Value']` and `body('Get_current_booking')?['Status']?['Value']`.
- **Date handling:** Create event (V4) requires date-no-timezone values. Convert UTC SharePoint values to `Pacific Standard Time` and select `(UTC-08:00) Pacific Time (US & Canada)` so daylight-saving time is handled.
- **Boundary overlap:** Calendar View can return an event ending exactly at the requested start. Filter actual overlaps with `event start < slot end` and `event end > slot start`.
- **Schema caching:** after adding/deleting SharePoint columns, switch an action's List Name away and back to refresh fields. Verify internal names and avoid creating duplicate display-name columns.
- **Self-trigger warning:** the decision flow updates StudioBookings and retriggers itself. ApprovalProcessed guards prevent duplicate appointment/decline processing.
- **Historical Bookings attempt:** the existing DevRel Studios Bookings page, service, and Stage A/B/C room mailboxes were configured in July 2026, but the active implementation pivoted to SharePoint + Power Automate because connecting Bookings to the service calendar was unreliable.
- **Guest vs. directory member:** typing a name and choosing "Use this name" adds a **Guest** — role locks to Guest and the calendar-availability toggle is greyed out. Must use **Search Directory** and select the real mailbox for the toggle to enable.
- **Troubleshooting room visibility in the Bookings staff picker:**
  ```powershell
  Get-Mailbox -RecipientTypeDetails RoomMailbox | Select-Object DisplayName,PrimarySmtpAddress,HiddenFromAddressListsEnabled
  Set-Mailbox stageA@learntv.onmicrosoft.com -HiddenFromAddressListsEnabled $false
  Set-Mailbox stageB@learntv.onmicrosoft.com -HiddenFromAddressListsEnabled $false
  Set-Mailbox stageC@learntv.onmicrosoft.com -HiddenFromAddressListsEnabled $false
  ```
- **Open risk:** Bookings may not accept room-type mailboxes as calendar-affecting staff. If Search Directory fails after propagation, fall back to a workaround (e.g., shared/user mailboxes per stage).
- **Room mailbox creation (already done), for reference:**
  ```powershell
  New-Mailbox -Room -Name "DevRel Studio - Stage A" -PrimarySmtpAddress stageA@learntv.onmicrosoft.com
  Set-CalendarProcessing -Identity stageA@learntv.onmicrosoft.com -AutomateProcessing AutoAccept -AllowConflicts $false
  Add-MailboxPermission -Identity stageA@learntv.onmicrosoft.com -User learntv@learntv.onmicrosoft.com -AccessRights FullAccess -AutoMapping $false
  ```
- **Possible enhancement:** Power Automate flow to auto-sync operator time-off → Stage A room calendar (removes the manual mirroring step).
